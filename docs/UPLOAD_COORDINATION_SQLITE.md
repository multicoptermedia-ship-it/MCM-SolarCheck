# SQLite upload coordination prototype

`SQLiteUploadLeases(database, lease_seconds=60)` provides an opt-in, token-owned coordination table shared by cooperating processes accessing **the same SQLite database**. It implements `hold(customer_id, project_id, filename)` for the existing optional `file_locks` interface on the filesystem upload store and upload reconciliation. Busy leases raise `UploadLeaseBusy`; they are not silently ignored. Expired leases may be reclaimed; stale tokens cannot renew or release a successor's lease.

**Not production-ready:** `hold()` does not automatically renew leases, and a process whose lease expires may continue writing. It has no fencing token enforced by storage, no crash-safe atomic commit across SFTP and SQLite, and no protection against non-cooperating writers. The SQLite database must be on a suitable shared coordination host, not copied separately to each worker. Do not place SQLite directly on unreliable network/SFTP filesystems. Production requires a centralized transactional coordinator with fencing and heartbeat/renewal, plus IONOS SFTP integration tests and explicit deployment configuration. Nothing is automatically enabled, deployed, or billed by this prototype.
